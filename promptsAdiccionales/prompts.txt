--PROMPT PARA CREAR SPEC.MD

/speckit.specify

Documenta retrospectivamente el hotfix que ya está implementado.

Analiza el diff actual de Git, las pruebas relacionadas y el comportamiento
observable de la aplicación.

La especificación debe describir qué problema resolvemos, el comportamiento
esperado, los escenarios principales, los casos límite y los criterios de
aceptación.

No propongas una nueva implementación y no modifiques el código.
No copies detalles técnicos dentro de los requisitos funcionales.


--PROMPT PARA CREAR PLAN.MD
/speckit.plan

Genera un plan técnico retrospectivo basado en la implementación existente.

Inspecciona el diff de Git y documenta:
- causa raíz;
- componentes afectados;
- solución aplicada;
- decisiones técnicas;
- riesgos;
- pruebas realizadas;
- posibles efectos secundarios.

No rediseñes la solución ni modifiques el código.




--PROMPT PARA CREAR TASKS.MD

/speckit.tasks

Genera las tareas correspondientes al hotfix ya implementado.

Marca como completadas únicamente las tareas que puedan verificarse mediante
el diff, las pruebas o los cambios existentes.

Mantén como pendientes las validaciones, pruebas o documentación que todavía
no hayan sido realizadas.
